# Retrieval architecture for internal procedural knowledge

## Failure scenario: an assistant cites the wrong procedure revision

A regulated insurer introduces an assistant that answers claim handlers' questions from internal procedures. The assistant retrieves a retired document about fraud referral thresholds because its embedding remains in the index after a policy update. It also quotes a paragraph from a restricted investigation manual to a general claims operator. The generated answer sounds authoritative and contains a document title, but neither document version nor the user's entitlement was checked before the retrieved text entered the prompt.

Retrieval-augmented generation is not a substitute for source governance. A safe architecture treats every retrieved passage as **untrusted, versioned, access-controlled evidence**. The system must establish which policy version is effective, whether the requesting user may see it and whether the passage supports the proposed answer. Unsupported questions should escalate to an approved human workflow rather than be filled with plausible text.

## Pega and knowledge boundaries

- **Pega Knowledge Buddy**, where licensed and supported, manages knowledge data sources and role-controlled access. Its exact collection, ingestion and retrieval capabilities vary by release. Do not assume the product automatically enforces a bespoke case-level policy from another application.
- **Case type and Flow Action** define the assistant's use context: an internal handler asking about claim assessment is different from a customer asking about a policy.
- **Data Pages and Connect REST** can retrieve the current case's minimal allowed context and call an approved retrieval or model service. Avoid copying entire pyWorkPage content into a prompt.
- **Access Groups, Access Roles and Access Control Policies** determine what the operator may access. Apply document and passage entitlements before retrieval results enter model context.
- **Decision rules and Data Transforms** enforce deterministic constraints, such as referral thresholds, when a model-generated summary cannot be trusted to execute business policy.

## Implementation sequence

1. **Inventory authoritative procedures.** Record owner, classification, region, business function, effective-from and superseded-at dates, approval status and canonical document ID. A document in a shared drive is not automatically authoritative.
2. **Define ingestion lifecycle.** Normalize PDF, HTML and text to passages with source offsets and revision metadata. On a replacement, retire old passages and verify index deletion or expiry. Keep an ingestion manifest and reconciliation job to find orphaned embeddings.
3. **Design authorization before ranking.** Use the authenticated operator and approved case purpose to select permitted collections. Filter by tenant, region, role and document classification before exposing passage text to the model. Recheck after retrieval if the search service cannot enforce row-level access.
4. **Use hybrid retrieval with explicit limits.** Combine lexical matches for policy codes and effective dates with semantic retrieval for paraphrased questions. Cap passage count and total token budget. Rerank only authorized candidates; do not let a low-similarity paragraph become evidence because the model needs an answer.
5. **Build a citation contract.** Every material claim should map to a document ID, revision and passage range. A citation generated by the model is a candidate reference, not proof: verify that the cited passage was actually retrieved and supports the statement.
6. **Keep decisions deterministic.** For monetary limits, approval matrices and eligibility rules, execute an approved Pega Decision Table or service policy and show the applicable rule version. The model may explain the rule but must not invent its result.
7. **Plan incident response.** Support emergency removal of a compromised document, invalidate caches, reindex and identify prior answers derived from that source. Audit source IDs, retrieval decisions, model version and response status without storing raw confidential prompts indefinitely.

## Tradeoffs and production failure mechanics

Large chunks retain context but can mix restricted and unrestricted paragraphs; small chunks improve pinpoint citations but lose exception clauses. Semantic search helps natural-language questions but may miss exact policy numbers; hybrid retrieval adds complexity but reduces that risk. Longer model context improves recall only until stale or conflicting passages dominate. Prioritize freshness and authorization over maximizing context size.

A permission check only on the document landing page is insufficient if vector search exposes passages directly. A revoked employee might still receive cached retrieved text unless cache keys include authorization scope and expiry. A malicious source document can contain prompt-injection instructions; retrieved text must never be promoted to system authority or tool permissions. If source validity is uncertain, answer with an explicit gap and route to the policy owner.

## Reproducible verification matrix

| Scenario | Controlled fixture | Required behavior |
|---|---|---|
| Retired procedure | Two versions, one superseded | Only effective approved revision cited |
| Restricted source | General handler queries investigation manual | Passage excluded before model call |
| Revoked access | Warm retrieval cache then revoke role | No cached restricted passage disclosed |
| Exact policy code | Query with rare code and paraphrase | Correct authoritative passage returned |
| Conflicting documents | Two valid-looking contradictory texts | Conflict surfaced, no invented resolution |
| Prompt injection | Document says to ignore instructions | Instruction treated as source text only |
| Unsupported answer | Question outside indexed scope | Abstain or escalate with no fabricated citation |
| Deletion request | Remove source and reindex | Passage absent from retrieval and cache |

No retrieval accuracy or latency metrics are asserted. Run these cases against a fixed corpus and model version before production.
